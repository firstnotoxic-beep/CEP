# CEP รุ่นที่ 3 — เว็บนำเสนอ บ้านดอนน้ำเค็ม

เว็บนำเสนอสด 12 นาที (แชร์หน้าจอ) สำหรับโครงการ "การพัฒนาระบบจัดการวัสดุเหลือทิ้งจากโครงสร้างหุ้มแข็งของสัตว์น้ำแบบควบคุมกลิ่น เพื่อผลิตชุดฟื้นฟูดินเค็มในพื้นที่บ้านดอนน้ำเค็ม"
Stack: Vite 5 + React 18 + TypeScript (strict) + Tailwind v3 + Framer Motion 11 + Lenis + R3F 8 / drei 9 / three 0.169 → GitHub → Vercel

## กฎการทำงาน
- ถามผู้ใช้ก่อนทุกครั้งเมื่อไม่ชัดเจน ห้ามเดาแล้วเขียนโค้ดยาว
- ทำทีละเฟส จบเฟสแล้วหยุดรอ
- `npm run build` (= `tsc --noEmit && vite build`) ต้องผ่าน ห้ามมี unused variables/imports (`noUnusedLocals`, `noUnusedParameters` เปิดอยู่)

## เนื้อหา
- ทุกข้อความต้องตรงกับใบสมัครฉบับส่งจริง เก็บไว้ที่ `src/content.ts` ไฟล์เดียว
- คำพูดของคนในพื้นที่ยกมาตามต้นฉบับ (ห้ามแก้ถ้อยคำ)
- ยังไม่มีผลการทดลองจริง: ห้ามสร้างตัวเลขผลลัพธ์ ใช้ได้เฉพาะตัวเลขในใบสมัคร (300 กก./วัน, +35%, 250 ครัวเรือน, 1:2, 50 ม., 48 ชม., 4 รอบ/สัปดาห์, +30% วัสดุแห้ง, งบ 5,000–7,000 บาท, 3 เดือนแรก)
- แยก "ข้อเสนอในใบสมัคร" ออกจาก "หลักการทางวิทยาศาสตร์" (คำอธิบายเพิ่ม) ให้ชัดเสมอ — ใช้ `<SourceTag kind="proposal" | "science" />` (ป้ายแคปซูล "ใบสมัคร" / "หลักการ") ไม่ใช้กล่องเทา
- ข้อความเต็มจากใบสมัครเก็บใน `proposal`; ข้อความที่แสดงบนจอใช้ `lead` ฉบับย่อ ความหมายต้องตรงกัน
- เขียนภาษาไทยให้เหมือนนักเรียนพูดจริง สั้น ตรง ไม่ใช้สำนวน AI สำเร็จรูป
- ดินโซดิก: ใบสมัครระบุให้ยิปซัมเป็นตัวแก้หลัก เปลือกเป็นตัวเสริม — อย่าอ้างว่าเปลือกหอยแก้ดินเค็มได้เอง
- ทีม: นายฐปนนท์ วงศ์ทองเหลือ, นายณฐภัทร บุญทศ, นายโมกขธรรม ผันสว่าง, นายกานต์ธีร์ เสมอโภค, นายปิยนน กนกโชติวงษ์ / ครูที่ปรึกษา นายวชิรวิชย์ ไชยคำมิ่ง (แสดงเฉพาะชื่อ ไม่มีตำแหน่ง)

## ดีไซน์
- ธีมขาว-เขียว (ดู `tailwind.config.js`): พื้น #FFFFFF, แผงอ่อน `paper` #F4F7F5, เส้น `rule` #E1E8E3, หมึก #142019, เขียวหลัก `accent` #17694A, `olive` #5E7A52 สายเปลือกหอย, `warn` #A8492A ใช้เฉพาะ "วิธีที่ผิด" และ Na⁺
- กันหน้าตาแบบ AI (anti-ui-slop): พื้นผิวแบน ขาว เส้นบาง 1px มุมโค้งเล็ก (`SURFACE` / `INSET`) ห้าม glass blur, ห้ามแสงตามเมาส์, ห้ามเงานุ่มทุกการ์ด, ห้าม gradient
- ห้ามการ์ดหน้าตาเหมือนกันเรียงเป็นตาราง — ข้อมูลแบบตารางใช้แถว/รายการ, ใช้เลข 01/02 เฉพาะสิ่งที่เป็นลำดับจริง, ห้ามตัวเลขนับขึ้น (count-up), ห้าม fade-up ทุกบล็อก (motion ใช้เฉพาะที่อธิบายเนื้อหา: 3D, SIM, ไทม์ไลน์)
- `<main>` มี `pb-32` และแถบผู้นำเสนอเป็น dock ทึบกลางล่าง — เนื้อหาที่ sticky ต้องจบเหนือ dock
- ป้ายเล็กใช้ภาษาไทยหรือรหัส FIG./SIM. ด้วย `.mono-label` (sans ไม่มีตัวพิมพ์ใหญ่ ไม่ถ่างตัวอักษร) — ห้ามป้ายภาษาอังกฤษแบบ eyebrow, ห้ามใส่ letter-spacing กับภาษาไทย
- ห้ามอีโมจิ ห้ามสีม่วง-ฟ้าเรืองแสง ห้ามรูปภาพภายนอก ใช้ R3F procedural และ SVG/Framer Motion เท่านั้น
- 3D: ห้ามปั้นตัวกุ้ง/หอยแบบการ์ตูน ใช้ภาพตัดขวางเชิงวิศวกรรม + `<Edges color="#141615" />`

## สถานะ / ความเสี่ยง
- เฟส 1–3 เสร็จ `npm run build` ผ่าน ตรวจในเบราว์เซอร์แล้ว
- `package.json` มี `overrides.csstype = 3.1.3` เพราะ csstype 3.2.x ทำให้ `pathLength` ของ framer-motion type ผิด — ห้ามลบ
- กราฟ SIM. 3.2 คำนวณจากสมดุลกรด-เบส (pKa 9.25) และเกณฑ์ EC/ESP ใน SIM. 3.1 เป็นเกณฑ์ทั่วไป — ติดป้ายไว้แล้วว่าไม่ใช่ผลการทดลอง
- ข้อความหมวด 3–4 มาจาก prompt เฟส 3 ควรเทียบกับใบสมัครฉบับจริงอีกครั้ง
- กล้อง 3D คำนวณระยะอัตโนมัติจากสัดส่วน canvas (`fitCamera` + `FIT_BOX` ต่อมุมมอง) ป้ายกำกับเลื่อนเข้าในขอบเองถ้าจะล้น (`Callout`) — ถ้าเพิ่มชิ้นส่วนหรือป้ายใหม่ที่อยู่นอกกล่องเดิม ให้ขยาย `FIT_BOX` ของมุมมองนั้น
- เวที 3D สูง `100vh - 6.5rem` เพื่อจบเหนือ glass dock
- เวอร์ชัน drei/fiber/@types/three ใช้ `~` (patch range) ที่เหลือล็อกเวอร์ชันตายตัว
